# Agent-choice-welfare storyboard template

Use this when an agent's choices, adjustment, or heterogeneity connect to a
welfare or policy object. The agent may be a household, firm, investor,
student, patient, government, platform, or worker.

| Time | Learning goal | On-screen words | Visual action | Conceptual handoff | Evidence/status |
|---|---|---|---|---|---|
| 0:00–0:07 | Define the decision problem | [choice 1], [choice 2], [choice 3] | Reveal each alternative from one origin | Preserve choices as later outcomes and welfare inputs | Model or setting |
| 0:07–0:20 | Introduce the change | [shock, treatment, policy, or state] | Change payoffs or availability without moving the origin | The same agent now faces a different menu | Definition + baseline |
| 0:20–0:32 | Make heterogeneity concrete | [state with more options] vs [state with fewer options] | Compare controlled menus or constraints | The state predicts different adjustment | Mechanism |
| 0:32–0:46 | Introduce evidence | One identifying sentence | Move from schematic choices to the released empirical object | Evidence recovers or disciplines the same margins | Design + manifest |
| 0:46–1:00 | Show response heterogeneity | One result sentence | Draw directly labeled paths, estimates, or contrasts | Responses become interpretation inputs | Figure or table |
| 1:00–1:17 | Build welfare or policy value | direct payoff + value of responses | Add one word term while activating its choice margin | The decomposition now has economic intuition | Theory + evidence |
| 1:17–1:28 | Interpret | for whom · relative to what · over what horizon | Return to the changed choice menu | Answer the opening decision problem | Supported result |

Before coding:

- State the baseline, sample, dates, horizon, discounting, and units.
- Keep positive and negative realizations separate when the paper evaluates them
  separately.
- Reuse choice labels in the agent view, response objects, and welfare build.
- If the paper has no welfare result, name the actual policy or objective
  function rather than forcing a sufficient statistic.
- Add named settled and transition frames to `project.toml`.
